# 分镜候选切点句末与真实停顿修复设计

## 授权、目标与范围

用户在[上一批验收](../records/2026-10-05-visual-state-continuity-acceptance.md)后批准“按建议继续”。本项只修候选粗筛两个已复现的运行时问题，先零费用回归，再有限重跑一次分镜。不继续旧已停止批次，不重拍全片。

目标：句末标点粘到后字时仍保留自然的既有合法边界；长字发声不冒充停顿。结构合法与画面事件正确继续分别验收。

直接在 `dev` 主工作区工作，不创建分支/worktree。本项不改原 timing、sourceSpans、正文、boundary ID、时间投影、schema、正式 prompt、模型/路由、数据库及原视频，不增加生产 LLM 调用次数，不引入本地语义判断或自动 reviewer 门禁。

## 根因与方案选择

原文第一句末尾合法 `boundary:2880:11` 在“漏”后、“。玄”不可拆 span 前，旧筛选丢掉此点，却因片段“。玄”含句号把 `boundary:3120:13`（玄｜奘）保留为句末。C3 位于“里｜漏”，相邻边界相差 560ms，但当前左右 token 实际无发声间隔为 0ms；差值包含右字发声及其后的停顿。

比较过三种做法：继续加 prompt 不能恢复候选中丢失的点；恢复全量边界会重新增加编号复制负担；本次采用修正粗筛判定，不增加模型调用或改正式合同。用户已批准此最小方向，不重复请求确认。

## 句末筛选

沿 `sourceText` 的 UTF-16 位置扫描连续标点/空白范围（Unicode P、Z 及空白），仅含现有句末字符 `。！？；…` 的范围参与句末筛选。对每个范围，在**已有合法 boundaries** 中选择位于其闭区间内且 sourceOffset 最大的一项。

- 标点附左字：选现有标点后边界。
- 标点附右字：标点后位置若在不可拆 span 内，则选现有标点前边界，不造点、不猜时间。
- 独立标点或连续标点/空白：优先范围内最靠后的合法点，避免仅因一个标点形成两个相邻句末候选。
- 一个不可拆 span 含“甲。乙”而范围内没有合法边界：不新增句末候选；仍可按真实停顿及原有短稿回退规则处理。

这只是标点结构与合法边界查找，不做中文分词、人物名单、语义打分或事件推断。扫描和有序边界查找使用单向游标，避免每个标点重复扫描所有边界。

## 停顿筛选与兼容

由 boundary 的 `leftTokenId` / `rightTokenId` 查原生 token，停顿条件为 `right.startMs - left.endMs >= 400`。边界来自已验证的不可拆 sourceSpans，零时长成员仍遵守原生共享端点，不把 token 内部端点放回候选。

首尾必含；句末候选与真实停顿候选取并集；原有不足三项时回退全量的保护保持；顺序及 `C1..Cn` 连续编号、四字段候选输出形状不变。既有持久化计划的真实 boundary ID 仍可投影，历史计划不按新编号重解释。

本次选择集合及编号会改变，旧输入哈希不再相同。已有冻结口播和旧计划不失效或重写；新生成使用新集合。2026-09-12 设计中的“片段含句号/相邻边界差”规则由本设计替换，宏观“句末或真实停顿”方向保持。

## 验证与费用

自动化覆盖：真实最小“。玄”附着和“里｜漏”零间隔、标点前后附着、独立标点、标点在 span 内且无合法点、400/399ms 实际间隔、长发声无停顿、共享数字 span/零点成员、首尾/回退/编号、来源哈希与旧投影不变。已有错误停顿测试改成真正测左右间隙，不为迎合旧错误结果保留原断言。

另覆盖连续标点/空白跨多个 span 的最右合法选择，以及句末前代理对的 UTF-16 偏移。负向粗筛测试必须保留另一固定入选锚点，使首尾加锚点至少三项，避免短稿回退遮住排除行为。

回归最小范围：`storyboard-narration-timing`、`storyboard-narration-prompt`、`storyboard-generation`，以及直接相关 narration 合同测试；backend typecheck 用于代码改动验证，失败区分已有基线。无需前端构建或浏览器 UI 验收，因为没有 UI 改动。

零费用验证、独立规格及质量审查通过后，使用原 338 字文案、75,170ms 原口播和三份已提交 prompt，在新实验目录重跑一次 `deepseek-v4-flash` 分镜。派发前核对输入仅候选表变化及原保护文件/hash，记录新旧候选与输入/hash；maxAttempts=1、max_tokens=8192，拒绝第二次网络派发和结构重生，不激活产物、不写数据库。

生产 `generateStoryboardPlan` 的口播模式仍有最多两次结构尝试；本实验分别在 gateway 的第二次 `invokeStructuredPrompt` 前及 fetch 的第二次网络请求前拒绝，不能只靠 provider 的 `maxAttempts=1` 宣称结构重生已禁用。

本轮前累计含历史预留 47.8204155 元，总计 50 元余额 2.1795845 元。本批进一步限制为 **最多 0.50 元，含失败调用**；按既有保守高峰未缓存价输入 2 / 输出 8 元每百万 token，以 UTF-8 字节数及 2048 余量计输入上界，输出最多 8192，派发前必须满足上界，否则停止。未知失败费用保留预留；有完整用量后复算，账户实际账单未核验，不挪走历史预留。

只做此一次分镜，不生成全局/分段/图片/H3。逐段人工审阅自然边界及当前事件对应，允许氛围/引语/余韵，禁止把结构通过等同视觉问题解决。仍提前关键事件则停止，不有限额度内偷偷重试。
