# 入镜角色场景服饰补全设计

## 目标与证据

用户授权修复核心四图验收中的玄武门主角造型遗漏，不继续冠服细节优化。原验收要求仍为同人可辨认、场景换装、关键动作与人物关系正确；本次只解决场景服饰遗漏。

`sb_004` 原分镜只明写背景武士披甲；最新 v1.6.0 global 的李世民 `visual_description` 已提供便服或甲胄参考，v1.5.0 分段输出却只写背景披甲武士，没有主角衣着。compiler 正确只注入稳定身体身份；实图 PA 仍是参考中的灰袍。输入 builder 没有丢掉造型字段。

## 方案

只扩展分段 planner 现有身份／造型职责规则：`image_prompt` 逐个说明入镜角色，尤其主角的当前场景服饰，不能用背景人物衣着代替。原分镜明写时优先忠实保留；未明写时结合当前叙事功能及 `visual_description` 中适用的造型补足。保留原剧情、人物、动作及身份，不将参考服装固定为跨镜制服。

不加本地语义推断、不改 schema、compiler、global、优化器或媒体执行；不写死李世民／玄武门／甲胄，不展开精确冠服形制。

## 验收与停止边界

- 合同回归与 prompt 治理通过只证明规则和编排，不冒充 LLM 语义通过。
- 复用批准的新 global，只新调用一次 chunk_002；其他输出回放，实际运行正式 generation／compiler／validator。检查主角衣着、人物动作与宫门原文。
- 文本通过后复用 P1 原始参考字节，在隔离 QA 数据库仅换 `sb_004` 的正式 compiler 输出；内置浏览器只生成一张，目视验面貌与换装。
- 沿用原 50 元累计预算，起点 5.655347 元；单次 LLM 预留最多 0.902 元，图片估算 0.20 元。失败即止，不重抽、不扩大全片。宫门出图遵从偏差单独记录。

## 风险

分镜未明写衣着时的补足仍由 LLM 判断，单样本不证明所有故事稳定；生图也可能忽略已写出的状态。旧计划不会自动重规划，历史失败保留。
