# 口播静音受控替换设计

适用项目：`history-video-forge`
日期：2026-09-16
关联：`backend/src/modules/narration/narration-timing-normalizer.ts`、[静音容错对齐设计](./2026-09-15-narration-silent-skip-alignment-design.md)

---

## 背景与问题

静音容错对齐已覆盖两类供应商改写：**静音删除**（跳过）与**重复静音折叠**（`……`→`…`）。第三类是**静音替换**——供应商把标点改写成另一个不同的标点（`——`→`；`、`。`→`，`）。这类目前整篇失败、白付一次付费调用；此前靠白名单逐条枚举（`——`→`，`/`—`）。

为什么不能简单枚举：未知替换无法穷举；而"给每个静音字符加任意标点候选"会与既有候选产生重复路径，需要成本分层配合（同一 normalized 文本下每个 block 至多多出一项替换候选，靠**候选构造**避免重复，不再依赖"路径唯一"这一判定）。

## 设计

`mapSentence` 的静音 block 增加一类候选：**替换为另一个静音标点**。

1. **候选来源**：**动态**——只要 normalized 当前位置的字符与本源范围不同且满足静音判定（`\p{P}\p{Z}\s`），就为该 block 生成一项替换候选（不枚举目标，覆盖各类 dash / 引号 / 变体与半角↔全角方向）。早期版本用固定 46 项目标集，因无法穷举而被本形态取代；同一 normalized 文本下每个 block 至多多出一个替换候选，不会与白名单/折叠候选产生同成本重复路径。
2. **成本 = 被替换源范围字符数 + 1**：`Choice` 增加可选 `cost`（默认 0）。原样/白名单/折叠仍为成本 0，故已知变体永远优先；替换只在无零成本路径时启用，作为**未知替换的兜底**。成本必须严格高于同块跳过成本：过低（如固定 1）会把长 run 的替换排在跳过之前而引到错误源字符；与跳过持平则会与换行空候选打平（该打平自 2026-09-17 起由确定性仲裁取舍而不再整篇失败，但仍会让两条读法成本相同、失去"已知变体优先"的确定序）。
3. **units 诚实映射**：替换候选的 unit 指向该 block 的完整原文范围（该源位置被读成了这个标点），token 区间与来源映射保持真实。
4. **多解由仲裁处理（2026-09-17 起）**：多个 source 标点竞争同一 normalized 字符时（如 `甲。、乙`→`甲，乙`），两条替换路径同成本。早期实现按"唯一最优"直接拒绝（fail-closed）；现改由[同成本多解仲裁](./2026-09-17-narration-alignment-tie-arbitration-design.md)按确定性规则选一条——差异限于静音区（block/unit 级不变；供应商把标点粘在正文上的 word，其 token 区间起止会随静音归属移动，正文源位置不变）。
5. **预算**：DP 成本上界 = 跳过预算（静音字符数，上限 `MAX_SILENT_SKIP`）+ 替换额外开销（每个 block 至多一次的 +1，上限同为 `MAX_SILENT_SKIP`；按**全体** block 计而非仅静音 block——正文单字替换通道同样需要额外开销，否则纯正文文本预算为 0、替换不可达）；match 与 skip 共用同一守卫，超预算只记录截断并输出 `skip_budget` 诊断，绝不越界访问成本分桶。
6. **目标集约束**：替换候选只在 `SILENT_PATTERN.test(normalized[offset])` 成立时生成（运行期守卫），防止"正文被读成正文"突破正文不可替换边界；正文 block 另有单字替换通道，条件同为非静音、非数字。
7. **安全边界不变**：仅静音 block 生成替换候选；正文（汉字/字母/数字）仍不可替换或跳过；不支持插入（normalized 必须被 match 完整消耗）。

## 与既有机制的关系

| 供应商行为 | 机制 | 成本 |
|---|---|---|
| 原样 | 原样候选 | 0 |
| 已知改写（白名单） | 白名单候选 | 0 |
| 重复标点读成单个 | 折叠候选 | 0 |
| **标点改写成另一标点（未知）** | **替换候选（本设计）** | **源范围字符数 + 1** |
| 标点被吞 | 跳过转移 | 源范围字符数 |
| 吞正文 / 插入 | 不支持，fail-closed | — |

## 已知残余覆盖面（设计取舍）

- 替换目标是**动态**的（normalized 当前字符即目标），覆盖面不再受枚举限制；每个静音 block 至多多出一项替换候选。
- **符号类目标仍不可达**：`～`(U+FF5E)、`+`、`=`、`<`、`>`、`$`、`^`、`|`、`~` 等属 `\p{S}` 而非 `\p{P}\p{Z}\s`，不满足静音判定，运行期守卫会直接排除。若供应商把标点改写为这类字符，归一化侧仍整篇失败。
  已知残余风险：`NARRATION_SAFE_GRAPHEME`（生成前白名单）放行 U+FF5E，故该字符可进入生产文案——需要另行机制（如生成前预检收窄或专门映射）才能覆盖。
- 替换为"成功 match"，不产生 `silent_skip` 诊断；观测兜底替换需从 token 来源反推。


## 补充：正文单字等长替换（2026-09-16 实测触发）

诊断（公共前后缀聚焦差异区）定位到真实失败：供应商把生僻字做**同音/形近归一化**——`怛罗斯` → `达罗斯`（等长替换，故长度差只反映标点）。这是正文层改写，此前的静音容错不覆盖。

设计：单字符 block 与目标同为正文类（非标点、非空白、非数字）时才生成替换候选，成本 = 2（严格高于原样匹配 0）；多处替换与标点替换可叠加；漏读（删除）与新增（插入）仍 fail-closed。**来源仍指向原文位置**，故字幕/切片保持原文写法（供应商读音与字幕显示的差异属供应商侧行为，映射本身唯一）。

预算同步：`budget = min(silentTotal, MAX_SILENT_SKIP) + min(blockMeta.length, MAX_SILENT_SKIP)`（第二项按全体 block 计；替换额外开销按"每个 block 至多一次"计），否则纯正文文本预算为 0 而使替换不可达。

回归：真实失败文案（470 字，三处 `——`→`，` + `怛罗斯`→`达罗斯`）一次性探针 26ms 对齐通过。**单位更正（2026-09-17）**：本条当时记的"467 tokens"是单位错误——467 是 `spokenText.length`（供应商归一化后文本长度），token（词）数为 424；两者出自**同一批、同一 `audioHash`**，不存在"两批不同"。逐字节重放结论见 2026-09-17 设计文档。

## 明确不改

- shared schema（`spokenText` 全等、覆盖检查、token 非零宽约束）；
- 投影/吸附/重生、字幕层、口播链路；
- 白名单机制（保留为首选路径）。

## 验证

- 单测：`——`→`；`、`。`→`，`、`！`→`？` 等未知替换通过且 token 来源指向原标点范围；白名单路径仍优先（成本 0）；两个标点竞争同一目标时确定性仲裁（见 2026-09-17 设计）；吞正文/插入仍拒绝。
- 回归：既有 normalizer 用例全绿（当时的 60 项）（原样/白名单/折叠/删除路径不受影响）。
