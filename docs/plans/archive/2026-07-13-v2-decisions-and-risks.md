## 1. 待人工决策清单

每项给出推荐方案、备选方案、取舍和当前状态。所有决策需要人工确认后才能进入实施。

### D1：RBAC 粒度

| 项 | 内容 |
|---|---|
| 推荐方案 | admin/user 两角色，不细分 permission |
| 备选方案 | 有限 permission set（如 user_manage、system_config、cross_user_view） |
| 取舍 | 先简单，收益证明再扩展。当前少量私有用户场景不需要复杂权限引擎。 |
| 状态 | `推断`，`待确认` |

### D2：初始管理员 bootstrap

| 项 | 内容 |
|---|---|
| 推荐方案 | CLI 命令 `admin-bootstrap` 创建首个 admin |
| 备选方案 | env var 配置默认密码（不推荐） |
| 取舍 | CLI 强制显式设置密码，避免默认弱口令。 |
| 状态 | `推断`，`待确认` |

### D3：Session 存储

| 项 | 内容 |
|---|---|
| 推荐方案 | 数据库 Session + HttpOnly cookie |
| 备选方案 | JWT（无状态） |
| 取舍 | 数据库 Session 可撤销、可审计。JWT 难以主动失效。 |
| 状态 | `推断`，`待确认` |

### D4：凭据存储（P0.3）

| 项 | 内容 |
|---|---|
| 推荐方案 | env 引用（第一版），ProviderCredential 表只存 env var 名称 |
| 备选方案 | 加密存储（需引入 KMS 或本地加密） |
| 取舍 | env 引用简单，与现有部署兼容。加密存储增加复杂度，当前非目标。 |
| 状态 | `推断`，`待确认` |

### D5：模型目录（P0.3）

| 项 | 内容 |
|---|---|
| 推荐方案 | 代码配置 + 数据库配置混合 |
| 备选方案 | 纯数据库配置；纯代码配置 |
| 取舍 | 稳定模型代码配置（版本控制），运营模型数据库配置（admin 可调整）。 |
| 状态 | `推断`，`待确认` |

### D6：RunSnapshot 粒度（P0.3）

| 项 | 内容 |
|---|---|
| 推荐方案 | 每次生成一条 |
| 备选方案 | 每阶段一条 |
| 取舍 | 每次生成一条平衡可追溯和存储。每阶段一条过细。 |
| 状态 | `推断`，`待确认` |

### D7：Prompt 真相源（P2）

| 项 | 内容 |
|---|---|
| 推荐方案 | 保留 `prompts/`（当前），不未经审查迁移 |
| 备选方案 | 迁移到顶层 `prompts/` 或独立 package |
| 取舍 | 与 AGENTS.md 规定一致。迁移需独立设计 + 规范同步。 |
| 状态 | `推断`，`待确认` |

### D8：事件库与 EventRegistry 关系（P1）

| 项 | 内容 |
|---|---|
| 推荐方案 | EventLibrary 引用 EventRegistry（避免双真相源） |
| 备选方案 | 合并为单一表 |
| 取舍 | EventLibrary 是正式事件库，EventRegistry 是 LLM 归一化记录。职责不同。 |
| 状态 | `推断`，`待确认` |

### D9：预算控制（P1）

| 项 | 内容 |
|---|---|
| 推荐方案 | 软提示（第一版），超预算只警告不阻塞 |
| 备选方案 | 硬限制（超预算停止） |
| 取舍 | 软提示灵活，硬限制可能导致生成中断。 |
| 状态 | `推断`，`待确认` |

### D10：媒体文件授权下载

| 项 | 内容 |
|---|---|
| 推荐方案 | file-routes 增加 owner 校验 |
| 备选方案 | 签名 URL（时效限制） |
| 取舍 | owner 校验简单，与现有路由兼容。签名 URL 增加复杂度。 |
| 状态 | `推断`，`待确认` |

### D11：密码策略（P0.1）

| 项 | 内容 |
|---|---|
| 推荐方案 | argon2id（memoryCost=19456, timeCost=2, parallelism=1）+ 最小长度 12 字符 |
| 备选方案 | bcrypt；更短最小长度 |
| 取舍 | argon2id 是 OWASP 推荐。12 字符适合私有系统。 |
| 状态 | `推断`，`待确认` |

### D12：Session TTL（P0.1）

| 项 | 内容 |
|---|---|
| 推荐方案 | 7 天滑动续期 + 30 天绝对上限 |
| 备选方案 | 更短或更长 TTL |
| 取舍 | 7 天平衡可用性和安全性。30 天绝对上限防止无限 session。 |
| 状态 | `推断`，`待确认` |

### D13：IDOR 响应码（P0.1）

| 项 | 内容 |
|---|---|
| 推荐方案 | 404（不泄漏资源存在性） |
| 备选方案 | 403（明确拒绝） |
| 取舍 | 404 防止攻击者通过响应码判断资源是否存在。 |
| 状态 | `推断`，`待确认` |

### D14：disabled 用户 session 处理（P0.1）

| 项 | 内容 |
|---|---|
| 推荐方案 | 方案 A：依赖 Auth Middleware 检查 user.status，不主动撤销 session |
| 备选方案 | 方案 B：停用时批量撤销所有 session |
| 取舍 | 方案 A 实现简单，方案 B session 表更干净。 |
| 状态 | `推断`，`待确认` |

### D15：管理员内容修改边界（P0.1）

| 项 | 内容 |
|---|---|
| 推荐方案 | 完全禁止 admin 修改业务内容，只允许读取/转移/重试/恢复 |
| 备选方案 | 允许 admin 代管修改（审计） |
| 取舍 | 禁止避免责任不清。如果确实需要修改，通过 owner 账户操作。 |
| 状态 | `推断`，`待确认` |

### D16：项目成员（P0.2）

| 项 | 内容 |
|---|---|
| 推荐方案 | 不实现项目成员，只做 owner + admin |
| 备选方案 | 实现项目成员表 |
| 取舍 | 当前无协作需求。未来再设计。 |
| 状态 | `推断`，`待确认` |

### D17：CSRF 防护（P0.1）

| 项 | 内容 |
|---|---|
| 推荐方案 | SameSite=Lax cookie + same-origin policy |
| 备选方案 | SameSite + CSRF token |
| 取舍 | SameSite=Lax 对大多数场景足够。CSRF token 更严格但复杂。 |
| 状态 | `推断`，`待确认` |

## 3. 风险优先级排序

按"概率 × 影响"排序，top 5 需要优先缓解：

1. **R-P0-1 IDOR 未完全修复**（高 × 高）—— 集中授权层是核心缓解。
2. **R-P0-3 disabled session 未失效**（中 × 高）—— Auth Middleware user.status 检查。
3. **R-P0.3-1 ProviderJob 重复付费**（中 × 高）—— 幂等合同 + 显式 opt-in。
4. **R-X-1 P0 范围过大**（中 × 高）—— 严格拆分。
5. **R-X-2 Task 8.5-9/8.5-10 未完成**（高 × 高）—— 明确前置依赖。
