# 角色一致性验收整改设计

## 背景与已批准范围

用户要求在内置浏览器验收角色一致性，并已批准按推荐方案修复。2026-10-03 隔离环境实测发现：定妆图出现同人多套服饰与插画风；称帝分镜仍沿用紫袍佩剑；无参考图文案误称无角色命中；供应商任务成功后仍为 prepared。

本设计分为三个顺序执行、独立提交的整改单元。原始证据位于未跟踪的 `storage/acceptance-20261003/`，其中 `live-prompt-evidence.json`、`live-final-evidence.json`、`acceptance-checklist.json` 记录原始输入、请求、输出与验收范围。原两次生图累计系统估算 0.40 元；本轮实现和离线验证不新增付费调用。

## A：稳定身份与场景服饰分离

### 数据与兼容

`ArtBibleCharacter` 增加 `identity_description`：中文描述可跨镜保持的年龄区间、脸型、五官、体型等身份特征，不能混入衣服、冠帽、兵器、动作或背景。原 `visual_description` 保留为角色整体视觉与场景造型参考，不再作为新计划的完整身份锚点。

持久化 v1/v2 schema 将新字段设为可选非空字符串，旧计划继续读取，不做批量迁移。新生成的 global draft 要求每位角色提供非空 `identity_description`；缺失只进入现有一次结构修复路径，修复失败按既有结构错误退出。本地只检查字段形状，不判断描述是否语义合格、不从旧文本用正则抽取身份。结构修复 prompt 需要说明这个字段的语义，不扩大可修改路径。

### 规划、编译与优化

资产全局规划 prompt 明确稳定身份与造型描述的区别；分段意图 prompt 明确当前分镜决定服饰、冠帽、兵器、姿态和场景。身份描述保持稳定；不把定妆图服饰当作所有镜头的制服。正式 prompt 在 `prompts/` 更新版本与变更记录。

编译器拼接 `[角色锚点]` 时优先使用 `identity_description`。定妆图同样只消费稳定身份，采用符合时代的单套中性服饰、单人正面全身、纯色背景，不携带兵器，不呈现同人多姿态或服装对照。保留现有 16:9、2048×1152、参考图数量、模型和成本规则；不新增阶段、LLM 调用或自动重试。

定妆图接入 `visual_tone` 与 `global_prompt_prefix`，不再无条件添加与项目画风相冲突的写实要求。画面共同的时代/无现代物品约束继续成立；只有定妆图调整风格拼接，其他分镜画风传播不在本单元扩大重构。

旧对象没有新字段时保留 `visual_description` 作为兼容回退，不伪造稳定身份、不重写冻结的 prompt。旧计划的冲突不能声称自动消除；应用新规则需用户显式重新规划。prompt optimizer 使用新身份字段，并允许按当前分镜修正旧锚点中冲突的造型，保留角色名与稳定身份；不得沿用“完整锚点一字不改”的规则。

### 验收

离线测试覆盖 v1/v2 旧计划可读、新字段可读、空值拒绝、新 global 缺失字段触发精确路径修复；编译输入以同一身份、不同服饰的两镜验证锚点不附加整段多套造型；定妆图保留项目画风、单人单造型；旧回退显式保留。prompt 合同与治理检查覆盖版本、中文与字段语义。真实画面是否保持同脸、服饰是否正确，必须另行授权付费复验，离线绿不能代替目视结论。

## B：参考图文案

`frontend/src/utils/asset-sheets.ts` 在 `character_sheet_task_ids` 为空时显示“未配置角色定妆图参考”，不推断角色命中情况。已有参考、未生成参考的标签保持原含义。单测与真实内置浏览器验证旧计划页面刷新后的文案；不新增生成按钮或修改任务绑定。

## C：供应商任务生命周期

执行引擎在现有 prepare → submit → poll 流程调用现有 job repository 更新方法：提交成功写 submitted、providerJobId、提交响应与首次 submittedAt；实际尝试轮询前写 lastPolledAt（异常也保留尝试时间，上下文检查失败而未调用 poll 时不写）；取得结果后写最新非空响应和 running/completed/failed 状态，终态写 completedAt；远端失败保留 errorCode/errorMessage。poll 未提供响应时保留已知提交响应，不能用空值清掉已有对账依据。

提交或轮询异常且尚未远端终态时写 failed 与异常信息。远端已 completed 后的下载/归一化失败只使本地 execution 失败，不能把已完成的远端 job 改成失败；保留其终态响应。`NarrationSourceError` 沿用现有抛出与记账语义，不把上下文过期冒充供应商失败。prepare 前失败没有 job，不创建虚假记录。更新不改变防重身份三元组、不增加提交或重试；保留原始请求、费用记账与路由。

repository 更新时首次进入 submitted 补 submittedAt，重复提交态更新不改首次时间；既有终态时间保持首次终态时间。使用独立 SQLite 测试验证状态与响应可重载，不能只检查内存。已有 prepared 历史记录不做猜测回填。

提交返回后先保留本次观测时间与回执，再写入账本；提交态写入暂时失败、后续失败态恢复写入时携带该已知时间。失败处理中的 job 更新继续抛错时，仍须先尝试既有费用记账再传播异常；所有写入持续失败则保留最后成功持久化的事实，并拒绝报告本地执行成功。

## 原始请求验收清单与结束口径

| 项目 | 本次证据要求 | 开始状态 |
| --- | --- | --- |
| 定妆图只包含一人一种造型，并遵循项目画风 | 编译测试；真实新图目视需另行预算 | 部分修 |
| 同人跨镜稳定，造型服从当前分镜 | schema/规划/编译/优化合同；两镜真实图目视需另行预算 | 部分修 |
| 参考图正确选择和注入，重跑仅替换目标镜 | 保留已有验收证据并回跑 character sheet harness | 已修 |
| 无参考图文案不误判角色命中 | 单测与内置浏览器刷新 | 未修 |
| 供应商任务记录实际状态、任务 ID 与响应 | 执行引擎测试和 SQLite 重载 | 未修 |
| 旧计划与人工上传仍可读，不自动覆盖旧图 | 兼容测试、浏览器与差异检查 | 已修 |

完成报告逐项区分已修、部分修、未修、未验证。代码与确定性行为通过后，真实画面质量仍为未验证，不能声明角色一致性整体验收通过。
