# 角色定妆图全身构图整改设计

## 任务与原始验收范围

用户要求使用内置浏览器验收角色一致性，已同意按推荐整改，并于 2026-10-03 新增最多 **50 元**付费预算。此前三图真实复验仅部分通过：单人写实、角色面貌延续、分镜造型切换、参考注入和任务账本通过，但完整 2048×1152 定妆图仍是半身。本设计只解决这个构图缺口，并验证改动不会破坏参考图作用。

继续沿用 dev 主工作区、隔离 QA 数据库和内置浏览器；不覆盖旧冻结计划和图片，不改生产数据、模型、计价、参考绑定、全局身份合同或自动重试。新 global 语义、全片稳定性和精确历史形制不是本设计的通过条件，继续单独标注。

## 方案比较与推荐

1. **先保留横图，明确镜头距离和完整入画范围（推荐）**：仅修改确定性布局模板，维持 16:9、2048×1152；合同变化最小，但必须真实验证脸部仍能作为参考。
2. **同一布局改成竖图**：若横图两张中任一仍裁切，追加两张 9:16、1152×2048 对照；像素数不变，保留身份、画风、负面词和模型。竖图可能改善全身空间，但属于新计划尺寸默认值变更，不能用推测代替证据。
3. **接受半身图**：保留较大面部尺寸，但不能满足已明确的全身要求，因此不选。

已有一次半身结果不足以断定尺寸是根因。先把含糊的“正面全身、面部清晰”改为可检查的镜头要求，横图两张都达标即停止竖图比较，避免无必要的付费调用和合同修改。

## 确定性布局候选

只替换 `asset-plan-prompt-enrichment.ts` 的 `CHARACTER_SHEET_LAYOUT`，身份、项目画风、时代约束的顺序和来源保持现有结构：

> 定妆参考图，单人正面自然站立，镜头拉远的全身远景，头顶至双脚及脚下地面完整入画，人物居中且四周留白，符合时代的单套中性服饰，简洁纯色背景，无兵器、无同人多姿态、无多套服装对照、无其他人物、无文字、无分镜构图

这是已有确定性编译模板的布局约束，不增加正式 LLM prompt、局部语义提取、语义 validator 或 reviewer 门禁。不得通过裁图、扩图、拼贴、自动图像修补把失败原图包装为成功。

若横图失败、竖图两张均达标，才把新 sheet 的 compiler 默认值改为 `9:16` / `1152*2048`，并同步设计合同和编译测试；旧冻结计划继续按旧参数执行。若两种方案均失败，保持未修，终止本批调用，先分析结果再决定下一项独立任务。

## 有界实测与费用

本设计最多 **8 次生图，估算 1.60 元**，计入新增 50 元总预算；不是耗尽预算的目标。每次 n=1、一次提交，无失败自动重试；正常 GET 查询不算新增生图。供应商账单未核对时明确使用系统估算。

顺序执行：

1. 李世民候选横图 H1、H2，共 2 次；两次均通过则停止候选比较。
2. 仅横图不达标时，执行同提示词竖图 V1、V2，共 2 次；失败即停。
3. 使用选定模板生成李渊两次，检查另一年龄/体型和脸部可辨，共 2 次。
4. 使用最后选中的李世民、李渊图重生成甲胄镜和衮冕镜，共 2 次，核对角色延续、造型切换及实际参考字节。

每次生成前保存完整候选输入和基线，使用独立 QA 计划/manifest 版本，生成按钮在内置浏览器点击一次。按新 phase 起点的 job/usage IDs 统计新增费用，不复用已经用完的旧授权预览。每批完成后检查任务 ID、次数、状态、真实请求、费用和完整源图，再进入下一批。新 job 数或费用异常、尺寸/模型偏离、服务错误时停止新增调用。

## 验收与边界

| 项目 | 达标证据 |
| --- | --- |
| 正面全身 | 完整原图可见头顶、双脚、脚下地面和边缘留白；无腰/膝/脚部裁切 |
| 单人中性参考 | 一个人、一套服饰、简洁背景，无武器、拼贴、多姿态或多套服装 |
| 身份和画风 | 符合显式人工 QA 身份，面部可辨，与冻结写实画风一致；不把人工夹具当作新 global 的结果 |
| 参考可用性 | 甲胄、衮冕场景保持同人观感，服饰由各自分镜决定；实际注入哈希等于选中的新 sheet |
| 账本与更新范围 | 新 job 完整持久化、每次仅一次尝试、费用未越界；只更新本设计四个目标任务，sheet 不进入分镜路由 |
| 回归 | 编译器测试、角色 sheet runtime harness、后端 typecheck；单测只证明提示词/参数传播，不证明画面质量 |

逐项使用已修、部分修、未修、未验证标注。两角色各两次只是有界小样本，不能声称全片、多轮概率保证或精确初唐形制通过。
