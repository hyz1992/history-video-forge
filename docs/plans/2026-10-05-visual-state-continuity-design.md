# 分镜语义对应与视觉状态连续性设计

## 目标与授权

用户已批准三处正式 prompt 的小步修改，保留 Flash、H3、全 API 视频策略及现有流水线。目标是解决画面提前演出后文事件、行旅负载缺失、衣物磨损与困顿状态不连续的问题。真实验证最多新增 2 元，包含失败调用；仍受此前总计 50 元限制。

已有对照与费用基线：[玄奘 Flash 同输入对照](../records/2026-10-05-xuanzang-flash-quality-replay.md)。本轮前累计含历史预留 47.6936535 元，可用 2.3063465 元；本轮使用更小的 2 元上限。

## 范围与职责

只修改以下三处正式中文 prompt，每处分别验证、审查、提交：

1. `storyboard.planner`：v1.5.1 → v1.6.0，负责当前口播事件与画面的对应，以及合法候选中的语义切分。
2. `asset-planning.planner`：v1.6.0 → v1.7.0，负责全片状态安排及必要的普通场景器物。
3. `asset-planning.segment-intent-planner`：v1.6.0 → v1.7.0，消费已冻结状态，把可见状态落实到图片和视频意图。

不改 TopicPackage、script writer、数据库、API、shared schema、provider、路由、时间投影、自动重试与 semantic reviewer。旧稿、旧片、原项目活动指针保持。本轮玄奘验证使用原先已确认的 338 字文案及 75,170ms 口播，拒用前轮未过下限的新稿。

## 现有通路与最小方案

`ProjectArtBible` 已有顶层 `consistency_notes: string[]` 与 `props`，全局 planner 收到全片脚本和分镜；`buildSegmentIntentPlannerInput` 把冻结的 `art_bible` 传给每个分块。第一版利用这条通路，不新建状态对象。

### 分镜语义对应

先明确每段原文正在发生的主要事件，再选择画面与候选边界。关键动作、转折与发现结果按口播发生的顺序展示，不能用同一主题的下一个事件替换当前事件。氛围、引语和余韵仍允许合理视觉表达，不要求每个字都有独立镜头。

只在已有合法候选内选择完整称谓和动作边界；没有合适短切点时优先保留完整语义，不猜时间、不改原文、不新增切点。保留全部现有来源、首尾覆盖、编号、trace、枚举和只读边界。该规则不等于新增本地人名黑名单或自动语义门禁。

### 全局状态安排

顶层 `art_bible.consistency_notes` 记录少量、按实际分镜 ID 或连续 ID 范围绑定的状态安排，说明人物/器物的持续状态、发生变化的事件，以及变化后仍需保留的状态。只针对故事中确有意义的变化，避免逐镜重复全段文字。

衣物使用痕迹、身体困顿、携带物及相对位置属于场景状态，不写进永久 `identity_description`，也不写成覆盖全片的 `global_prompt_prefix`。有必要的普通场景负载进入现有 `props`，说明形态、承载方式及持续关系；不能凭空制造重要道具、人数、装备数量或新剧情。

史料未明确的普通视觉还原必须克制，并在现有 `manual_review_notes` 说明推断边界。状态以脚本和已确认分镜为准，不能回改上游；发现冲突时在现有审阅说明中指出，不偷偷纠正事件。没有状态变化的题材不强行增加脏污、虚弱或磨损。

### 分段落实

按当前 segment ID 消费适用的顶层状态说明，把本镜看得见的两三项关键证据写进 `image_prompt`。保留已有主角服装、衣冠器物形状、身份/造型分离、动作瞬间及多人职责规则，避免重复堆叠。

视频意图与同镜锚点图延续相同的服装、身体状态及负载关系，围绕当前主要动作展开，不凭空增加新的状态转折或后文结果。局部特写只写合理入画的证据，不能为显示全部道具而破坏构图。状态说明缺省时沿用分镜与造型参考；说明与分镜冲突时保留分镜事件并记录风险，不由分段 planner 重写剧情。

## 验收与失败处理

自动最小验证仅证明正式 prompt 合同、来源/边界投影、输入传递、编译器和角色参考未回归，不证明真实语义质量。真实规划逐段人工审阅当前事件、自然边界、负载连续性、衣物状态及压力递进。

先生成一次分镜；语义不达标时停止付费验证。通过后生成一次全局设定和最多三个单段意图，分别覆盖行旅、困顿、恢复后的状态。普通合理还原不得冒充事实。

文字通过后，通过既有 provider adapter 在实验目录的 plan/manifest 上下文中生成三张关键锚点图，内置浏览器负责预览，不点击原项目全批生成。优先复用原已批准身份参考，记录角色映射、原图 SHA 与实际参考图数量/请求内容；身份与旧图冲突或静默降级为无参考时不能宣称一致性通过，须停止或先重新核算参考图费用。

三图全部通过后才验证一个自然完整、真实口播范围不超过 5 秒的段落。先调用 H3 adapter `prepare`，按实际 `duration_sec × split_total × 0.09` 检查预留不超过 0.45 元；v2 narrationRange 会覆盖参数时长，不能靠手写 duration_sec=5 或修改冻结口播范围降费。没有合适范围时视频标为未验证，保留三图结果。原始视频播放/抽帧检查视觉，同时听审多余人声、台词和明显音频瑕疵，原音轨与交付静音路径分开记录，不额外调用付费 ASR。

每项最多一次，失败计费、不自动返工、不重拍全片。本轮确需追加身份图时先重新核算总上界；关键图仍最多三张，总费用不超过 2 元，不追加目标图重试。

付费预检采用当前项目价目与保守 LLM 用量上界；文字阶段预留不超过 0.95 元，三图预留 0.60 元，5 秒 1080P H3 预留 0.45 元，合计最多 2 元。若实际输入上界无法满足预留，则缩小输入/验证范围或停止，不超支。账户实际扣款优先，全部未确认费用仍保留。

验收结果逐项使用已修、部分修、未修、未验证，并分别记录合同、真实文字、图片与视频证据。原始产物和失败证据保留。新的语义评审不接入自动门禁或主链路动作。

## 自审边界

此方案增加少量 prompt token，不增加生产链路的调用次数。复用字符串说明的可行性已由现有数据通路确认，但真实消费稳定性尚需验证；若多题反复失败，另行设计结构化合同，不能在本轮顺手扩展。玄奘是验收案例，正式 prompt 不包含玄奘、行囊或沙漠的固定模板。
