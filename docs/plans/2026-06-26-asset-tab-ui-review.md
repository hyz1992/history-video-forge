### 1.2 当前交互流程

```
进入资产Tab
  ├─ 首次加载中 → 骨架屏
  ├─ 加载失败 → 错误卡片 + 重试
  ├─ 无规划 → 「开始生成资产规划」按钮
  ├─ 规划生成中 → 全屏阻塞层（StageGenerating, 5s 轮询）
  ├─ 规划完成无manifest
  │    ├─ → 自动触发基础资产生成（tts/sfx/bgm）
  │    ├─ → 显示全屏「正在生成基础资源」阻塞层
  │    └─ 失败 → 重试按钮
  └─ 有manifest（正文区可见）
       ├─ 基础资产已自动完成（口播/字幕/运镜/音效/配乐）
       ├─ 概览卡显示待处理项（主要是分镜图/视频）
       ├─ 用户可：
       │   ├─ 「批量生成剩余资产」→ 确认对话框(含费用) → 全部生成
       │   ├─ 「重新生成全部资产」→ 二次确认(危险) → 全部重建
       │   └─ 逐卡片手动：单任务生成 / 上传 / 替换
       └─ 全部完成后 → 「确认并进入合成」
```

## 二、问题清单与优化方案

### 问题分类标签

- 🔴 **P0 问题**：影响核心可用性，必须在本次重构解决
- 🟡 **P1 问题**：用户体验明显受损，重构中优先处理
- 🟢 **P2 问题**：锦上添花，可在后续迭代中处理

---

### 2.1 全屏阻塞生成体验（🔴 P0）

**现状**：
- 资产规划生成和基础资产生成阶段使用 `StageGenerating` 组件全屏阻塞页面
- `shouldShowAssetGeneratingView` 在 `hasManifest=false` 时强制 `blockPage=true`（见 [asset-generating-view.ts:L74](file://d:/ai_learn/history-video-forge/frontend/src/utils/asset-generating-view.ts#L74)）
- 基础资产生成失败后，阻塞层消失，只显示重试按钮，用户看不到任何中间结果
- 轮询期间页面完全不可交互，用户只能等待

**问题**：
1. 基础资产生成包含 TTS + SFX + BGM，可能耗时 1-5 分钟，全屏阻塞让用户感觉"卡住了"
2. 用户无法在等待期间查看规划结果、预览分镜、调整提示词等
3. 失败后回退到空状态，之前已成功的部分（如 TTS 某几个 chunk）不可见

**优化方案**：

> #### 方案：渐进式加载 + 非阻塞生成态
>
> 1. **去除基础资产生成的全屏阻塞**：`asset plan` 完成后立即展示规划概览和分镜卡片骨架，基础资产在后台异步生成
> 2. **规划概览页保持可交互**：在规划概览卡中嵌入一个紧凑的生成进度条（而非全屏阻塞），用户可以折叠/展开查看详情，也可以提前浏览分镜卡片
> 3. **分镜卡片骨架态**：manifest 未就绪时以骨架/半透明态展示分镜列表，用户可看到所有 segment 结构但不可操作生成
> 4. **资产规划生成仍需阻塞**：因为此时连 segment 结构都没有，展示空壳无意义，但可以优化为半屏通知条 + 底部保留项目信息

**改动范围**：
- `asset-generating-view.ts`：`blockPage` 逻辑细化
- `AssetPanel.vue`：分拆规划生成阻塞 vs 基础资产生成非阻塞
- 新增或改造 `StageGenerating` 为内联进度条变体

**风险**：低。基础资产生成失败后已有 manifest 结构（TTS 可在 manifest 中标记 failed），不影响后续交互。

### 2.2 概览卡信息密度过高（🔴 P0）

**现状**：
资产生成概览卡（[AssetPanel.vue:L886-L998](file://d:/ai_learn/history-video-forge/frontend/src/components/asset/AssetPanel.vue#L886-L998)）囊括了：
- 进度条 + 完成数
- 7 类资产完成度 pills
- 待处理项 chip grid（可点击跳转）
- 成本结算（图片/视频/口播分项 + 合计）
- 「批量生成剩余资产」按钮
- 「重新生成全部资产」按钮
- 提示文字

**问题**：
1. 卡片纵向过长，用户需要滚动才能看到分镜卡片
2. "待处理项" 和 "批量生成" 是最常用的交互，但被埋在中间
3. 成本信息虽然重要，但不应该每次打开页面都占据同样的视觉权重
4. 7 类资产中，"运镜"、"音效"、"配乐" 大多数情况下都是 0/0（无需生成），占位但无信息量

**优化方案**：

> #### 方案：概览卡拆分为状态栏 + 可展开详情
>
> 1. **顶栏状态条**（始终可见，紧凑一行）：
>    - 完成进度 `8/12` + 迷你进度条
>    - 关键待处理摘要：`3 张分镜图待生成，1 个视频待生成`
>    - 「批量生成剩余」主按钮
>    - 「展开详情 ▼」折叠按钮
> 2. **展开详情区**（默认折叠，记住用户偏好）：
>    - 7 类资产完成度（只显示 `total > 0` 的类型，过滤掉"无需"）
>    - 待处理项完整列表
>    - 成本结算
>    - 「重新生成全部资产」
> 3. **成本信息降级**：默认折叠在详情区，每次生成完成后通过 toast 提示本次费用

**改动范围**：
- `AssetPanel.vue`：概览卡重构为紧凑状态栏 + 可折叠详情
- 新增过滤逻辑：`allTypeBreakdown` 只显示 `total > 0` 的类型

**风险**：低。只是 UI 重组，不影响数据流。

### 2.3 批量生成缺乏粒度控制（🟡 P1）

**现状**：
- 「批量生成剩余资产」一次性提交所有未完成项，包括图片和视频
- 用户无法选择"只生成图片，跳过视频"
- 用户无法选择"只生成 #3 #5 #7 这几个分镜"
- 确认对话框展示了总费用估算，但用户看到后无法反悔（只能全部取消）

**问题**：
1. 视频生成成本高（0.60 元/秒），用户可能只想先生成图片预览，再决定哪些分镜升级视频
2. 一次性提交所有图片任务可能导致并发问题或超时
3. 确认即全量，缺乏中间控制点

**优化方案**：

> #### 方案：分类型批量 + 复选框选择
>
> 1. **分类型批量按钮**：
>    - 「生成全部图片」（N 张，约 ¥X.XX）— 仅生成 `image_still`
>    - 「生成全部视频」（N 段，约 ¥X.XX）— 仅生成 `video_clip`
>    - 「生成全部剩余」（N 项，约 ¥X.XX）— 保留当前行为
> 2. **待处理项列表增加复选框**：允许用户勾选/取消特定项，然后「生成选中项」
> 3. **确认对话框优化**：显示分项明细而非只有一个总金额

**改动范围**：
- `AssetPanel.vue`：批量操作区 UI 重构
- `assets.ts` store：`generateAssets` 已支持 `taskIds` 参数，只需前端传参

**风险**：低。后端 API 已支持 `taskIds`。

### 2.4 分镜卡片导航与定位困难（🟡 P1）

**现状**：
- 分镜卡片纵向排列，数量多时需要大量滚动
- 「跳到下一项」只跳转到第一个待处理项
- 待处理项 chip 点击后跳转到对应卡片 + 闪烁高亮（2s），但跳转后卡片可能仍在视口边缘
- 没有目录/快速导航

**问题**：
1. 10+ 个分镜时，用户难以快速定位特定分镜
2. 「跳到下一项」只能线性前进，无法回退或跳选
3. 跳转后只高亮 2 秒，用户可能来不及注意

**优化方案**：

> #### 方案：侧边迷你导航 + 分镜状态条
>
> 1. **左侧固定迷你导航**（桌面端）：
>    - 纵向排列的分镜圆点（#1 #2 #3...），点击跳转
>    - 圆点颜色表示状态：灰=无任务，黄=有未完成任务，绿=全部完成，红=有失败
>    - hover 显示 tooltip：`#3 分镜图待生成`
> 2. **分镜卡片顶部固定吸顶**：当前滚动到的分镜卡片标题在滚动时保持可见
> 3. **键盘导航**：`j/k` 或 `↑/↓` 在分镜卡片间切换，`Enter` 聚焦当前卡片操作区

**改动范围**：
- `AssetPanel.vue`：新增侧边导航组件
- `SegmentAssetCard.vue`：状态色暴露给父组件

**风险**：中。侧边导航需要与滚动同步，且响应式布局需要考虑小屏。

### 2.5 生成状态反馈不精细（🟡 P1）

**现状**：
- 批量生成时只显示 `生成请求已提交，处理中... 当前 N/M 已完成`
- 单个任务生成时按钮变为 loading，完成后通过 toast 通知
- 没有按 provider 类型的进度分解（如 "TTS 完成，正在生成图片..."）
- 轮询间隔固定 5s，状态更新有延迟感

**问题**：
1. 用户不知道当前后端在做什么（TTS? 图片? 视频?），只能干等
2. 如果某个任务卡住了，用户无法知道是哪个
3. 单任务"生成"按钮的 loading 和全局 lock 是同一把锁，单个任务生成中所有卡片按钮都被禁用

**优化方案**：

> #### 方案：按任务粒度的进度可视化
>
> 1. **概览卡进度条细化**：使用分段进度条，每段代表一个任务类型，已完成段为绿色，进行中段为蓝色脉冲，待处理段为灰色
> 2. **分镜卡片内联进度**：当某个 segment 的任务正在生成时，卡片内显示 `⏳ 生成中...` mini 状态，而非全局锁死所有卡片
> 3. **全局锁改为任务级锁**：当前 `isGloballyLocked` 阻止所有卡片的操作按钮；应改为只在对应任务上显示 loading，允许用户在其他卡片上进行非冲突操作（如查看提示词、上传已完成分镜的文件）
> 4. **后端暴露 execution_state 的 `progress_phase`**：目前 `AssetPanel` 已读取 `execution_state.progress_phase` 等字段（[AssetPanel.vue:L113-L123](file://d:/ai_learn/history-video-forge/frontend/src/components/asset/AssetPanel.vue#L113-L123)），但仅用于规划阶段；应扩展到资产生成阶段

**改动范围**：
- `AssetPanel.vue`：锁粒度细化，进度条分段
- `SegmentAssetCard.vue`：卡片内联进度态
- `assets.ts` store：`isGenerating` 可能需要扩展为 `generatingTaskIds: Set<string>`

**风险**：中。锁粒度改动需要仔细测试并发操作场景。

### 2.6 提示词编辑工作流过长（🟡 P1）

**现状**：
- 智能优化：打开对话框 → 输入反馈 → 点击「生成优化版」→ 等待 LLM → 查看对比 → 点击「应用优化」→ 关闭对话框
- 手动编辑：打开对话框 → 编辑 → 保存 → 关闭对话框
- 每次操作只影响一个任务的一个提示词
- 无法批量优化某个分镜的所有提示词

**问题**：
1. "智能优化"操作步骤多（至少 4 次点击），如果对结果不满意需要重来
2. 没有"一键优化"（不预览直接应用）的快捷方式
3. 无法快速对比优化前后的提示词差异（只在对话框中可见）

**优化方案**：

> #### 方案：内联编辑 + 一键优化
>
> 1. **提示词区域支持直接点击编辑**（inline edit）：
>    - 点击提示词文本 → 变为 textarea → 编辑 → 点击外部或 Ctrl+Enter 保存
>    - 减少"打开对话框 → 编辑 → 保存 → 关闭"的开销
> 2. **智能优化增加「快速优化」模式**：
>    - 新增「一键优化」按钮（无需打开对话框），直接提交 LLM 优化 + 自动应用
>    - 优化完成后 toast 通知 + 提示词区域短暂高亮变化部分
>    - 保留当前「精细优化」对话框作为高级选项
> 3. **优化历史**：每个提示词保留最近一次优化前的版本，支持"撤销优化"

**改动范围**：
- `SegmentAssetCard.vue`：提示词区域改为可编辑，新增快速优化按钮
- 新增优化历史存储（可考虑 local state，不持久化）

**风险**：低。主要是 UI 交互改动，后端 API 不变。

### 2.7 分镜图/视频预览体验（🟢 P2）

**现状**：
- 预览区使用 220px 宽 × 9:16 比例（约 390px 高），卡片左侧列
- 多图轮播使用小圆点切换
- 点击图片/视频打开全屏浮层预览
- 浮层支持键盘左右切换和 Esc 关闭

**问题**：
1. 220px 宽度对于竖屏 9:16 内容偏窄，细节看不清
2. 轮播圆点太小（6px），容易误触
3. 全屏预览很好，但图片加载依赖 `artifactUrl` 直连，大图可能较慢
4. 没有缩略图条（thumbnail strip）预览所有已生成图片

**优化方案**：

> #### 方案：增大预览区 + 缩略图条
>
> 1. **卡片布局微调**：媒体区从 220px 增加到 260-280px（需要整体 grid 调整）
> 2. **轮播改进**：
>    - 圆点改为带缩略图的小方块（36×64px），或至少增大圆点到 10px
>    - 支持触摸滑动（移动端）
> 3. **全屏预览优化**：预加载相邻图片，减少切换延迟
> 4. **缩略图条**：多图任务在预览区下方显示缩略图条，当前选中项高亮

**改动范围**：
- `SegmentAssetCard.vue`：布局调整 + 轮播改进
- 可能需要图片懒加载/预加载工具

**风险**：低。纯 UI 优化。

### 2.9 自动生成逻辑脆弱性（🟡 P1）

**现状**：
- `autoStartBasicAssets` 函数有多个守卫条件：`canAutoStartBasicAssets`、`basicAssetsAutoStarted`、`isAssetsBusy`、`hasManifest` 等（[AssetPanel.vue:L540-L558](file://d:/ai_learn/history-video-forge/frontend/src/components/asset/AssetPanel.vue#L540-L558)）
- `watch` 监听 5 个响应式值的变化来触发自动生成（[AssetPanel.vue:L561-L583](file://d:/ai_learn/history-video-forge/frontend/src/components/asset/AssetPanel.vue#L561-L583)）
- 多个 boolean flag 协调（`basicAssetsAutoStarted`、`canAutoStartBasicAssets`、`basicAssetsGenerationFailed`、`isInitialAssetSnapshotLoading`）
- `onMounted` 中有 4 个分支路径（[AssetPanel.vue:L485-L537](file://d:/ai_learn/history-video-forge/frontend/src/components/asset/AssetPanel.vue#L485-L537)）

**问题**：
1. 多个 boolean flag 组合的状态空间很大，容易产生不可预期的交互
2. `watch` + `autoStartBasicAssets` 可能在非预期时机触发
3. 页面刷新后恢复生成中状态依赖 backend `execution_state.generating`，但轮询停止条件复杂
4. 基础资产生成失败后 `basicAssetsGenerationFailed = false` 的重置时机不明确

**优化方案**：

> #### 方案：显式状态机重构
>
> 1. **引入阶段状态机**（而非多个 boolean flag）：
>    ```ts
>    type AssetTabPhase =
>      | { kind: "loading" }
>      | { kind: "no_plan" }
>      | { kind: "plan_generating" }
>      | { kind: "plan_ready"; needsBasicAssets: boolean }
>      | { kind: "basic_assets_generating" }
>      | { kind: "basic_assets_failed"; error: string }
>      | { kind: "ready"; manifest: AssetManifest }
>    ```
> 2. **状态转换由单一 reducer 函数管理**，而非分散在各处的 `ref` 赋值
> 3. **自动生成改为显式触发**：规划完成后不自动开始基础资产，而是展示规划概览 +「生成基础资产」按钮（含费用预估）
> 4. **轮询停止条件简化**：统一使用 `execution_state.generating === false && current_status !== '*_generating'` 单一判定

**改动范围**：
- `AssetPanel.vue`：引入 composable `useAssetTabPhase`
- 新增 `frontend/src/composables/useAssetTabPhase.ts`

**风险**：中高。状态管理重构涉及面广，需要充分测试各种进入路径（直接进入、从 storyboard 确认后进入、页面刷新、生成中刷新等）。

### 2.10 错误处理粒度不够（🟡 P1）

**现状**：
- 加载失败：全页错误卡片 +「重试」
- 生成失败：toast 提示 + 按钮恢复
- `assetsStore.state.loadError` 和 `assetPlanningStore.state.loadError` 都是单一 string
- 无法区分"网络错误"、"后端超时"、"权限问题"等不同错误类型

**问题**：
1. 用户不知道失败原因，只能盲目重试
2. 批量生成中如果部分任务失败，成功的不被标记
3. 轮询连续失败 3 次后显示通用错误（[useStagePolling.ts:L51-L55](file://d:/ai_learn/history-video-forge/frontend/src/composables/useStagePolling.ts#L51-L55)），但对用户不够友好

**优化方案**：

> #### 方案：分级错误展示 + 部分成功处理
>
> 1. **错误分级**：
>    - `fatal`：网络断开/权限不足 → 全页错误卡片
>    - `transient`：超时/服务繁忙 → 内联警告 + 自动重试倒计时
>    - `partial`：部分任务失败 → 概览卡中标记失败任务
> 2. **执行状态细化**：在 manifest 中正确标记每个 `task_execution` 的 `status`：
>    - `failed` 的任务在概览卡中显示红色，卡片中显示失败原因
>    - 提供「重试失败项」按钮（区别于「批量生成剩余」）
> 3. **错误信息结构化**：后端返回 `{ error_code, message, recoverable }`，前端据此决定展示策略

**改动范围**：
- `assets.ts` / `asset-planning.ts` store：错误类型扩展
- `AssetPanel.vue`：分级错误 UI
- 后端 API 错误响应规范化

**风险**：中。涉及前后端协议对齐。

## 六、总结

当前资产 Tab 页功能完整、逻辑正确，但存在以下核心体验短板：

1. **全屏阻塞过长**：资产规划和基础资产生成共可能阻塞 3-10 分钟，用户完全无法交互
2. **信息架构混乱**：概览卡囊括太多信息，用户最需要的"批量生成"和"待处理项"不够突出
3. **批量控制粗糙**：用户无法选择只生成图片或只生成特定分镜，成本控制粒度不够
4. **状态管理脆弱**：多个 boolean flag 的组合难以维护，状态转换不够显式

建议优先解决 P0 的两项（阻塞体验 + 概览卡信息密度），然后分阶段实施 P1 和 P2 优化。每次改动保持小步、可验证、可提交。
