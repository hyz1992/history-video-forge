# 角色规划语义回修设计与实施计划

## 证据、范围与方案

沿用用户角色一致性验收、继续整改和最多 50 元的授权。前一轮七次真实规划调用已完成，18 段真实生成、compiler 与 local validator 通过，65 个任务、20 个依赖、无错误或警告；人工语义不通过，因此不进入原两镜生图任务。

问题分开回修，不新增阶段、schema、语义关键词校验、自动门禁或重试：

1. 全局身份虽与造型分开，但年龄未对应本片主叙事时点。脚本主时点为武德九年，模型却写李世民十九至二十岁、李渊五十岁；与已验收 H2/E2 约二十八岁/六十岁不相容。身份 prompt 明确先按本片主时点确定年龄阶段，无法可靠确认时用宽年龄阶段，不猜具体数字。不得硬编码本例人物、年份、生年或人工 QA 身份。
2. 分段规则埋在一条长约束中，真实输出仍把“登御座”替换为“正面立于御座前”，甲胄仅写术语，衮冕只写礼制名称和章数。将既有视觉规则拆成短而分工明确的约束：关键衣冠器物写能画出的外形、结构和颜色；连续动作选可见瞬间，保留原动作、人物位置及核心物件关系，不能替换成泛化站姿；多人角色职责遵从分镜，不补出新的关键人物。移除原重复表达，不堆叠口号或本例模板。

精确历史衣冠审校仍不在此小任务范围。年龄来源诊断见七调用记录；查证结果不作为生产 prompt 的硬编码资料。已有九图与七次 LLM 证据不可覆盖，原生产数据不动。

## 三调用有界语义复验

另外保存不可覆盖的 `scene-planner-repair-*` QA 探针及预检。保持原 18 段、script、topic、confirmed narration、双快照路线、人工冻结画风、720P 与模型。使用现有 `generateAssetPlan`、registry/gateway、输入 builder、compiler 和 `validateAssetPlan`。

最多新增三次供应商调度：一次新 global、一次包含 sb_004 的分块、一次包含 sb_016 的分块。其余四个分块明确重放首次真实调用的原始解析输出，保存来源哈希及 replay 事件，不能宣称本次重新生成全片。四块曾消费旧 global，回放只证明编排与结构合同，不能宣称混合计划的全片语义或人物一致性通过。回放不伪造供应商日志或 token。若既有结构检查要求额外修复，停止本小批，不增加第四次真实调用。

所有真实调用保持 `maxAttempts=1`、`maxTokens=8192`、`timeoutMs=120000`、系统与 JSON 输入 UTF-8 合计不超过 50000 bytes。单次最坏费用不超过 0.6804 元；新增三次最多预留 2.0412 元。原七次 LLM 保守估算 1.555362 元与新增预留合计不超过原 8 元 LLM 预留；合计十次调度。九图 1.80 元也继续计入原 50 元授权，不重设基线、不把本地 LLM 账本当零。调用前保存调度和费用预留，完整原始输出、effectiveRequest、token、attempt 和结算落盘；模型漂移、缺日志、失败或预算越界停止。

第一调用后先停在全局结果，父任务人工检查身份/造型分离与 H2/E2 兼容。只有通过才继续两个真实目标分块。失败不拿参考去迎合新身份。三调用结束后运行真实 local validator，并人工逐项核对可见衣冠、原动作瞬间、两主角/核心物件关系。语义不通过继续保留失败，不激活、不生图。
