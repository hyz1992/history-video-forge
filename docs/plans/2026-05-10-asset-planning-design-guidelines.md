# Asset Planning 阶段核心设计指导方针 (Design Guidelines)

> **文档受众**：即将执行 Asset Planning 架构设计的 Agent (如 Codex)。
> **文档定位**：本文件浓缩了前期高阶架构推演中关于成本、质量、解耦及项目特殊性的关键共识。在进行正式架构设计（Schema、API、状态机）前，必须强制对齐以下设计理念。

---

## 一、 阶段定位与核心边界

Asset Planning 是连接“纯文本/意图（Storyboard）”与“物理资产（图片、视频、音频）”的统筹中枢。

*   **输入**：`StoryboardPlan` (只读)
*   **输出**：`AssetPlan` (包含一系列具体的 `AssetTask` 任务清单)
*   **不做什么**：
    1.  **绝不干涉剧本或分镜**：不修改台词、不更改分镜结构。
    2.  **绝不死扣时间轴**：Storyboard 传来的 `hint_sec` 只是用来评估“该生成一张图还是两张图”的**预算表**。真正的合成时间轴，必须且只能由后续 Qwen3-TTS 生成后返回的绝对物理时长决定。
    3.  **不发起真实生成**：本阶段只负责“写任务单”（写出带 prompt、枚举配置的任务对象），不负责拿着任务单去调万相或百炼的生图生视频 API。

---

## 二、 架构必须解决的五大核心命题

在设计 `AssetTask` 和任务流转引擎时，必须将其以下五个核心命题融入到 Schema 与状态机中：

### 1. 全局美术设定集 (Global Art Bible) 前置机制
*   **痛点**：如果分段独立生成图片，会出现“同一角色长相不断突变”的崩坏灾难。
*   **强制设计**：在拆分单段视觉任务前，必须设计一个前置的 `ProjectArtBible` 提取与锁定逻辑。基于全剧本提取主角（如晏子、楚王）和核心场景的外貌/风格模板。
*   **落实要求**：所有的单段图像生成任务（AssetTask），其最终 Prompt 必须是：`{全局美术模板} + {单段具体动作描述}`，并建议共享同一个 Seed/风格参数。

### 2. 智能降级策略 (Smart Downgrade) 与 Remotion 配合
*   **痛点**：全盘调用图生视频大模型成本极高，且模型目前处理复杂动作（如吃饭、递东西）必定肢体崩坏。
*   **强制设计**：系统默认禁止大面积生成真实视频。
*   **落实要求**：针对 `content_type: live_action`，系统默认生成的任务应为 **“高质量静态图任务 + Remotion 空间运镜指令”**（由 `motion_hint` 决定是推、拉还是平移）。只有当遇到极强烈的动作，或用户主动在后续介入升级时，才生成真实 API 视频任务。

### 3. 半自动旁路机制 (Bypass / Manual Upload) —— 最高优先级特性
*   **痛点**：流水线内置的 API（如万相）生成质量往往不如用户手头的顶级外部工具（如 ChatGPT Plus / Grok / Midjourney）。
*   **强制设计**：必须在任务状态机（Task State Machine）中设计外部旁路注入能力。
*   **落实要求**：
    *   UI 层不要只给一个“自动生成”按钮，必须提供“复制终极 Prompt，并手动上传产物”的通道。
    *   `AssetTask` 必须支持类似 `WAITING_FOR_MANUAL_UPLOAD` 和 `COMPLETED_BY_MANUAL` 的状态。
    *   对于系统来说，只要该节点接收到了合法的物理文件（无论来自内部 API 还是外部上传），就可以向下流转。

### 4. 听觉张力映射 (Audio Tension Track) 的混合策略
*   **痛点**：纯靠口播拼接的视频像干瘪的 PPT，缺乏“爆款感”。背景音乐和音效不应该全部靠昂贵的模型生成。
*   **强制设计**：利用 Storyboard 传来的 `narrative_role` (如 opening, peak, turn) 自动埋入音频任务。
*   **落实要求**：
    *   **SFX（音效）**：优先设计“标签匹配本地库”机制（如检测到 `peak`，自动生成一条加载本地 `drum_boom.mp3` 的 AssetTask），而不是盲目生成 Text-to-Audio 的 Prompt。
    *   **BGM（配乐）**：按需从预设的情绪音乐库中抽取，或仅在极特殊情况下调用 Suno 等外部 API 生成。

### 5. TTS 全自动与单向控制权
*   **痛点**：如果允许用户上传音频，系统将无法获得精确的毫秒级时间戳信息，导致后期字幕和画面无法对齐。
*   **强制设计**：
    *   TTS 口播音频及其时间戳（推荐 Qwen3-TTS），是整个流水线的基石。
    *   **绝不允许**在此环节做手工干预或外部旁路上传。
    *   TTS 任务在设计时需明确：对于过长台词的自动切片策略，以及全局音色（VoiceID）的参数复用机制。
