# 唯一基准携带关系与镜头可见性设计

## 授权与证据

用户批准继续[上一批建议](../records/2026-10-07-global-load-retention-acceptance.md)：收紧唯一携带位置，区分物件持续存在与每镜可见，文字通过后验关键图。直接dev，不创建分支/worktree。

上一批正式global v1.8.0已落实普通行囊及恢复后的旧衣磨损保留，但真实输出仍写“背负或系于马背”“身侧或马背”；未选定基准，审核说明也重复任选关系。另写行囊“不得从画面消失”，与既有分段局部特写规则有张力。独立文字C0/I1/M1整体未过；未生图。

本设计只处理这一承载合同，不改分镜、口播、身份、身体恢复规则、schema、API、正式调用策略或模型设置；不把一次失败归因于模型整体能力。

## 方案与取舍

采用现有全局prompt句内替换：将基准关系写成唯一可执行选择，状态例外绑定已确认事件及分镜ID，并明确持续存在与镜头可见性分工。成本低，沿用现有props/consistency_notes字段及完整传入分段的builder。

新增结构化载位字段会牵动schema、compiler和供应商输入；本任务无需。单独换更贵模型不能保证解决合同允许多种解释的边界，当前不作此对照。

正式global升v1.9.0，仅替换“全局场景状态”第二条，第一条恢复保留及第三条事实/身份分工保持。拟定规则：

> 必须按人物处境判断是否需要普通行装：需要时写入现有 `props` 并说明形态，不需要时在 `manual_review_notes` 说明理由。对需持续携带的物件（包括原剧情已有物件），须选定唯一基准承载关系，写清承载者和具体位置，不并列给出任选位置；在状态安排中按分镜 ID 写明取用等已确认动作的携带变化及动作后是否归位。物件持续存在不等于每镜可见：局部近景只呈现合理入画部分，不为展示行装破坏构图。原剧情核心道具不能代替普通行装需求判断；不得新增关键道具、具体装备数量或新剧情。史料未证的普通合理视觉推断写入 `manual_review_notes`，说明推断边界，不冒充事实。

唯一指一个确定的基准安排，不强制全片不变、不限制已确认共同承载者人数、不指定玄奘或固定行李形式/数量。动作后是否归位依据已确认分镜；不得为填例外而补新剧情。普通视觉推断仍须披露。

仅三个正式文件：全局prompt、同目录changes、已有character-identity-prompt-contract测试。合同测试验证规则存在与治理，不判定真实模型文本语义，不接semantic reviewer自动门。
