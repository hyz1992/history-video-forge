# Records 状态说明

`docs/records/` 保存两类文档：

1. **历史运行记录与结论**：保存历史运行记录、质量检查、阶段结论、恢复说明和人工观察结果。这类文件的价值是追溯“为什么当时这样判断”，而不是直接定义当前系统应该如何实现。
2. **工程经验参考**：如旧项目的踩坑记录（`video-pipeline-engineering-notes.md`），用于在正式设计相关系统前提供输入约束和问题清单。

## 当前使用规则

- 新任务入口不要从 records 随机开始。
- 先阅读 `AGENTS.md`、[docs/README.md](../README.md)、正式架构文档和当前计划。
- 只有在需要解释历史决策、排查质量回退、核对某次恢复或验证输出时，再读取相关**历史记录类** records。
- 当准备开启某一个尚未设计的新阶段（如 asset planning / compose）时，必须先查阅对应的**工程经验参考类** records，将其作为设计防坑指南。
- 如果 records 与正式架构文档、Prompt Registry、harness 规则或当前计划冲突，以当前入口文档和正式规范为准。

## 归档边界

- records 通常不删除，因为它们是质量恢复、运行验证和人工判断的证据。
- 过期 records 不应被迁出或重写为当前规范。
- 如果某条历史结论仍然有效，应把它吸收到正式架构文档或当前计划中，而不是要求 agent 反复阅读旧 records。
