# V1 到 V2 过渡记录

日期：2026-07-10

## 1. 记录目的

本文记录 V1 高风险稳定化的交付边界、进入 V2 的依据，以及暂未展开设计但必须保留的后续方向。本文是阶段留痕，不替代正式架构设计。

## 2. V1 当前结论

已经完成并有代码或运行证据支持的能力：

- JSON 快照兼容加载、备份回退和原子写入。
- 后端构建失败传播、非回环地址绑定安全闸门。
- 测试存储隔离、媒体目录启动加载、全局音色持久化。
- 中断状态恢复、项目阶段互斥、真实请求取消。
- 项目级推荐轮次持久化、事件身份指纹、近期事件硬排除。
- 项目删除保护、`/healthz` 与 `/readyz` 分离。
- 前后端生产构建通过；关键稳定化回归通过。
- 内置浏览器完成三轮真实选题推荐。第三轮暴露近期事件再次进入结果的问题，已通过 `cd17b0ba` 修复。

不能扩大表述为“V1 全量测试全部通过”的事项：

- 全量 Vitest 在当前串行运行条件下曾超过 124 秒，尚无一次完整通过记录。
- topic runtime 仍有部分基于旧指纹/旧排序语义的测试需要校准。
- assets API 与 assets run service 仍有默认音色、视频 artifact、TTS plan 不可变性相关失败。
- 数据库快照仍可能包含本地调试项目；这不影响 V2 设计，但迁移前必须明确归属和清理策略。

## 3. 进入 V2 的决策

允许进入 V2 设计，首批只正式设计以下两个子项目：

1. 数据层基础架构：SQLite + Prisma、迁移、事务、文件资产边界、备份恢复。
2. 用户系统与管理员权限：管理员创建账号、登录会话、项目隔离、RBAC、审计。

V2 首批设计不包含公开注册、找回密码、邮箱验证、计费、多租户组织、云对象存储和远程部署平台。

## 4. 后续 V2 方向留痕

以下方向必须保留，但应分别完成 design + implementation plan 后再实现：

### 4.1 推荐系统增强

- 丰富历史时期、朝代、叙事情绪、事件类型、人物关系等筛选维度。
- 正式接通事件库与自定义选题入口。
- 继续维护事件身份、跨轮推荐记忆、同事件多角度模式之间的语义边界。

### 4.2 用户偏好与生成策略

- 支持 API 视频优先、Remotion 优先和成本优先策略。
- 持久化默认模型、音色、画面比例、视频生成方式等偏好。
- 管理员可以覆盖系统默认值，普通用户只能修改允许开放的个人偏好。

### 4.3 Prompt Registry 正式治理

- prompt 继续作为代码级资产统一管理。
- 正式 prompt 保持中文和 `language: zh-CN` 元数据。
- 迁移前必须处理当前 `harness/prompts/` 与“代码级资产位置”目标之间的规范冲突，不能直接搬目录。

### 4.4 模型性能与成本优化

- 建立首 token、完整响应、结构化解析、重试次数和调用成本指标。
- 对 GLM-4.7、GLM-5 及候选模型做同一任务集基准测试。
- 优先探索模型分层、任务拆分、严格结构化输出和缓存策略，不只做简单换模型。

### 4.5 内容策略配置化

- 先把历史故事领域做到合格以上。
- 把内容策略拆成可切换配置：事件字段、筛选维度、prompt 套件、validator、展示标签。
- 神话故事是最低优先级扩展，只允许在相似叙事模式和稳定配置接口形成后接入。

## 5. V2 设计闸门

- 先冻结用户、项目、文件资产和推荐记忆的归属模型，再写 Prisma schema。
- 现有 `backend/prisma/schema.prisma` 仅作为历史字段参考；它没有依赖、migration、生成 client 或运行时接线，且缺少当前 V1/V2 对象，不能作为增量升级基线。
- 新数据层从当前 `DbClient`、快照格式和正式 pipeline schema 建立模型对照表后，重新设计 Prisma 7 schema 与首个 migration。
- 迁移工具必须可重复演练、可生成报告，且失败不覆盖原 JSON 快照。
- 未完成项目所有权校验前，不开放非回环远程访问。
- 管理员权限不能通过前端隐藏按钮实现，必须由后端鉴权和授权中间件强制执行。
- 每个 V2 子项目单独设计、单独计划、单独验证、单独提交。
