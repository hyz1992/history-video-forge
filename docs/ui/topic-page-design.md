# 主题页面 UI 设计

## 1. 页面目标

让用户在一个统一页面中，以尽量低认知负担完成选题，并最终确认一个 `Topic Candidate Card`，由系统冻结成 `Topic Package`。

## 2. 顶层结构

页面使用 3 个 tab：

1. `系统自动推荐`
2. `事件库`
3. `自定义主题`

默认选中：`系统自动推荐`

## 3. 系统自动推荐 Tab

### 页面元素

- 轻量筛选区
- 主按钮：`开始生成选题`
- 候选列表
- 右侧详情抽屉

### 轻量筛选区

当前已确认只保留软偏好：

- 时代偏好
- 题型偏好
- 不要什么
- 长度倾向

说明：

- 这些只参与排序，不做强硬过滤
- 高级筛选可折叠，不抢主入口注意力

### 候选列表

- 展示 `3-5` 个 `Topic Candidate Card`
- 支持：
  - `换一批`
  - `固定这个事件，换个讲法`

### 详情抽屉

展示：

- 标题
- 一句话讲法
- 题型
- 范围档位
- 推荐理由
- 强场面
- 必讲节点预览
- 风险提示
- 确认按钮

## 4. 事件库 Tab

这里的对象是 `event`，不是 final topic。

流程：

- 浏览事件库条目
- 打开事件详情抽屉
- 点击 `为这个事件生成讲法`
- 系统生成 `2-3` 个 candidate
- 用户从 candidate 中确认一个

## 5. 自定义主题 Tab

流程：

- 用户输入事件名 / 成语 / 简介 / 描述
- 系统做事件识别与归一化
- 生成 `2-3` 个 candidate
- 用户确认一个

明确不再采用：

- 让用户直接编辑大量内部 draft 字段
- 把自定义主题做成 prompt 编辑器

## 6. 状态与结果

用户确认 candidate 后：

- 页面显示确认成功
- 系统冻结 `Topic Package`
- 项目状态推进到 `script_ready`
